## 2. 재질·조명·성능

| 항목 | 현재 | 문제 |
|---|---|---|
| 재질 | 전부 단색 MeshStandardMaterial (텍스처는 사무동 창문 캔버스 1장뿐) | 노멀/러프니스 맵 전무 → "장난감" 느낌의 2차 원인 |

| fps | 이 컨테이너는 SwiftShader(소프트웨어 GL)라 측정 무의미(~1fps) | 실기기 기준으로 QA 단계에서 재측정. draw call·셰이더 비용 기준으로 추정 관리 |
| 텍스처 메모리 | ~0.3MB (창문 캔버스 2장 + 바다 노멀) | 여유 큼 — PBR 텍스처 추가 여지 충분 |

## 3. 3·4·7번 "주황/검정 체크 무늬" 원인

**텍스처 누락이 아니라 사무동 창문 재질의 스케일·대비 문제.**
`Buildings.tsx`의 `makeWindowTextures()`가 256px 캔버스에 10×14칸 창문 그리드를 그려
`boxGeometry` 각 면에 **1회 반복**으로 입힌다 → 창문 한 칸이 실제 수 미터 크기로 과대.
밤에는 emissive 맵의 45% 랜덤 점등 창(주황 `#ffd984`)이 켜져(강도 1.0) 검은 유리와
교차하며 체커보드처럼 보인다. 7번(오션플라자)은 같은 텍스처에 파란 틴트+높은 metalness라
낮에도 파란 체크로 보인다. → A-2에서 실스케일 창문 띠 텍스처·커튼월 재질로 교체.

## 4. 개선 계획과 예상 성능 영향

(fps 영향은 노트북 내장 GPU 기준 추정치. 이 컨테이너는 소프트웨어 GL이라 상대 비용으로 관리)

| 단계 | 내용 | 예상 비용/이득 |
|---|---|---|
| A-1 렌더링 파이프라인 | HDRI IBL(절차 생성 .hdr), 카메라 추적 그림자(±38유닛), N8AO+SMAA+약한 Vignette, FogExp2, 시간대 3프리셋+노출 슬라이더 | N8AO −3~5fps(High만), 그림자 범위 축소는 **이득**(동일 해상도로 선명+컬링), IBL ≈0 |
| A-6 위험 레이어 | 바닥 전용 데칼·등고선·저층 맥동 기둥, 레이어 토글 | 오버드로 감소로 **+2~4fps** (현재 거대 반투명 기둥이 풀스크린 오버드로 유발) |
| A-2 재질 | 절차 생성 PBR 텍스처(1K), 재질 공유 | 텍스처 샘플 증가 −1~2fps, draw call 변화 없음 |
| A-3 건물 형태 | 톱니 박공·채광창·창문띠·셔터, 지오메트리 병합+인스턴싱 | 정점 수 증가하나 **draw call 1269→300 이하로 감소 → +5~10fps** |
| A-5 야간 조명 | 선택적 Bloom(threshold), 실광원 ≤10, 빛 웅덩이 additive 데칼 | 데칼 ≈0, Bloom은 기존과 동일 비용. 광원 수 제한으로 **밤 +2~3fps** |
| A-4 크레인 | 트러스 부재 InstancedMesh | 부재 수백 개가 instanced 1~4 call → ≈0, 디테일 대폭 상승 |
| A-7 바다·하늘·지형 | Water 유지(만 안쪽 감쇠), HDRI 하늘, 언덕 노이즈+원경 산 실루엣 | 산 실루엣 +2 call, ≈0 |
| A-8 라벨 | 줌 레벨·충돌 기반 LOD | DOM 라벨 수 감소로 **+1~2fps** |

### 외부 에셋 관련
이 작업 환경의 네트워크 정책상 Poly Haven / ambientCG 다운로드가 차단되어(연결 거부),
HDRI와 PBR 텍스처는 **numpy로 절차 생성**해 `public/hdri/`, `public/textures/`에 넣는다.
라이선스 문제 없음(자체 생성물, credits.md에 명시). 추후 실제 CC0 에셋으로 교체 가능하도록
파일 교체만으로 동작하는 구조를 유지한다.
